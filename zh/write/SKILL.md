# write — 学术章节成稿与溯源表写作

把"根据文献素材 + 自己的数据，写出一节可直接进论文的成稿"标准化。每写一节产出**两个文件**：成稿 `<章名>.md` 和过程文件 `<章名>data.md`。

## 铁律（不可妥协）

1. **严禁编造**。公式、参数、常数、统计数字、文献结论，必须有真实出处：来自用户计算表（如 main2.xlsx）或 Zotero 库里真实读到的原文。拿不准就标"待补"，**绝不许凭印象填一个看起来对的数**。
2. **每条语言2都可溯源**。成稿里每一句引用/转述/给参数的话，过程文件里必须对应：英文原句 + 中文翻译 + Zotero Key；中文文献给中文原句 + Zotero Key。
3. **数据口径以用户表格为准**。涉及公式参数（均衡因子、产量因子、样本数、时间范围、单位换算）时，先核对用户计算表，不套教材默认值。
4. **弃用有缺陷的文献表述**。读到某文献自身逻辑矛盾（如公式符号混用、判据自相矛盾）时，只采用其可核验部分，明确弃用矛盾部分，并在过程文件里记录"为什么不采用"。不能因为它是英文顶刊就照抄。
5. **先问后写**。章节主题、输出文件名、要覆盖哪些公式/结果、有无指定必引文献、加粗约定按哪种——没说清就先问，不要猜。
6. **【严重】分析性结论/实验反馈不得写入成稿**。写入 .md 的成稿只允许六类内容：研究对象与范围、数据来源、公式、参数取值、单位换算、处理方式（"用什么数据、怎么算"）。任何对"结果意味着什么"的解读、方法学告诫、实验洞察——例如"因而不能只比较单市年度升降""豫南低值不能据此推断用水效率高""容易忽略北部连续承压分布""不宜依据单年划定高低压区"——都属于给用户看的分析反馈，**只在对话里说，绝不写进 .md**。方法节尤其如此：方法节只写"做了什么"，不写"为什么这么解释结果"。凡是含"因而/不能/容易/不宜/据此/这说明/这表明/意味着"等解读意味的句子，一律先问自己：这是成稿该写的，还是我在给用户做分析？是后者就删掉，只在回复里讲。
7. **【结果/讨论章专用】数据描述必须往中心论点和实际意义上靠，但"数据→意义"的桥必须照文献搭**。方法节只摆数据；结果/讨论节不能只罗列趋势和范围（"先升后降""北高南低""波动上升"），那样写等于没回答"画图的目的是什么"。要把数据现象**往论文中心论点上引、往实际应用意义上收**。但这个引申必须守两条边界：① 不超出学术常识和现实条件——不能从"北部压力高"直接跳到"必须立即调水/必须限采"这种没有文献支撑的政策强结论；② "数据→成因→对策"的桥段模仿 Zotero 库里同类论文怎么写，引用它们的表述深度和措辞，不自己发明跨度。拿不准能引申到哪一步时，先引文献的结论口径，再把自己的数据嵌进去。
8. **【一次只写一节，严禁生成全文】**。本 skill 是逐节写作工具，不是全文生成器：
   - **一次只写一个二级标题或三级标题下的内容**（比如只写"3.1 水资源生态足迹模型"，不连着写3.2）。
   - **写完一节必须停下来**，把成稿和过程文件交给用户审核，等用户说"可以，写下一节"或"这里改一下"之后，才进行下一步。
   - **严禁主动连续写多节**、严禁自动开始下一节、严禁把引言+方法+结果一口气全写出来。
   - 下面的"分章节写作架构"只是各章节的**套路参考**（写引言时怎么组织、写方法时怎么组织），不是"现在把所有章节都写了"的指令。

## 两种语言（都必须模仿文献库的表述习惯）

**核心要求：语言1和语言2都不是"让AI自由发挥"，而是模仿用户 Zotero 库里同类论文的表达习惯。** 动笔前先读 2–3 篇中文文献的对应段落（学语言1的口吻）和 2–3 篇英文文献的对应段落（学语言2的句式），照它们的节奏写，不要自造一个通用的"学术腔"。

- **语言1（研究对象/数据处理/单位换算/段间衔接，不加粗）**：交代"用什么数据、怎么换算、怎么衔接"。**模仿库里中文地理论文（如黄林楠2008、郝帅2021、王健泉2024）同章节的写法**——它们怎么开头、怎么交代数据来源、怎么过渡到下一个公式，就照那个口吻。语言1不写分析性结论、不写概念定义。
- **语言2（学界定义/公式/参数/判据，全部加粗）**：与学界接轨的定义、公式、参数、判据。**模仿库里英文方法论文（如 Borucke2013、He2024）的写法**——它们怎么给定义、怎么列变量、怎么引判据，提取句式后用自己的中文转述，不照抄也不自造句式。

### 语言1 的反AI痕迹规则（高优先）

语言1 是最容易暴露AI的地方。写作时逐条自检：

1. **禁用高频AI/翻译腔套话**。以下表达一律不写：
   - 开头/铺垫："随着……的发展""在……的背景下""近年来""众所周知""毋庸置疑""具有重要的理论意义和现实意义"。
   - 衔接："首先/其次/再次/最后""一方面……另一方面""不仅……而且""值得注意的是""需要指出的是""综上所述""总而言之"。
   - 结尾空泛升华："为……提供了重要参考/依据/支撑""具有重要的指导意义""对……具有重要意义"。
2. **不写无信息量的过渡句**。每一句语言1都要带具体内容（研究对象、数据来源、换算方式、处理决定、与上下段的实际逻辑关系）。空转一句"本节将介绍……"这种删掉不影响理解的句子，直接删。
3. **拒绝长定语嵌套**。中文地学论文主谓宾紧凑，不写"基于XX方法构建的XX模型用于测算的XX指标"这种一层套一层的翻译腔长句；拆成短句。
4. **不用四字成语排比/对仗堆砌**（"举足轻重""不可或缺""至关重要""复杂多变""时空异质性"连用）。
5. **句式长短交错**。AI倾向全篇中等长度均匀句；刻意制造短句（8–15字）和稍长句穿插。
6. **语言1里出现的数字/事实必须来自用户数据或刚读过的文献**，不能用"大量研究表明""相关研究显示"这类无指向概括代替具体来源。
7. **语言1不承担概念定义**——定义、公式、参数是语言2的事；语言1只说"本文怎么处理、为什么这么处理"。

### 语言2 的引用纪律（高优先，杜绝幻觉引用）

语言2最大的风险是**根据题目/常识反推一句"某某曾指出……"**，实际并没读过那篇文献。规则：

1. **只引本会话真实读过的文献**。"读过"指：通过 zotero-cli `get fulltext` / `read` 读了该条目的全文或指定页，或读了它的 Zotero 笔记；不能只凭标题、摘要、或"这领域Rees(1992)肯定说过"来写引用。
2. **每句语言2必须能在过程文件里贴出对应原句**。写不出原句（英文原句或中文原句）的句子，**不得加引用角标**——要么去把原文读出来再写，要么改写成不带引用的语言1（作者自己的处理决定），要么删掉。
3. **严禁"看到题目就反推引用"**。禁止根据章节标题、关键词、常识去臆造"Smith(2020)认为……""已有研究表明……[n]"这类句子。没有原句就没有这句引用。
4. **可以综合，但综合必须建立在已读原句上**。把多篇已读文献的观点合并成一句中文概述时，过程文件里要列出所有被综合的 Zotero Key，且每个 Key 都有对应原句；不能"凭印象综合十几篇"。
5. **区分三种情况，分别处理**：
   - 单篇转述 → 一个 Key，贴该篇原句；
   - 多源综合 → 多个 Key，每个 Key 都有原句；
   - 作者自己的处理决定（如"本文按城市逐年计算产量因子，不采用外部固定值"）→ 这是语言1，**不加引用**，哪怕某文献做过相反选择。
6. **[n] 必须指向真实读过的条目**。角标编号只能对应参考文献列表里、且本轮实际打开过的文献；没读过的文献即使"应该引"，过程文件里标注"待补"，正文暂不出现该角标。
7. **发现文献原文与想写的意思对不上时**，改写成贴近原义的转述，不要硬套；对不上就放弃这个引用点。

**加粗约定全论文统一**：语言2（学界定义、公式、参数取值、判据、转述文献的句子）全部加粗；语言1（研究对象、数据处理、单位换算、段间衔接、作者自己的处理决定）不加粗。引言章也照此统一（不再按章节分两套）。

## 分章节写作架构（套路参考，不是一次写完所有章节）

不同章节套路不同，不要用同一套节奏写所有章。整体论证链：**领域需求 → 现有瓶颈 → 本文做法 → 关键证据 → 更广意义 → 边界**。

> **注意**：下面列的引言/方法/结果/讨论/结论架构，是你**写到某一节时**参考该节怎么组织，不是现在把这些全写出来。一次只写一节（见铁律#8）。

### 引言：漏斗式
1. 领域重要性（1-2段，落到具体问题）
2. 现有研究瓶颈（公允回顾已有工作，不是文献清单堆砌）
3. **明确说出空白在哪**（按下表六类对号，写清本文占了哪几类）
4. 本文直接回应这个空白（一句话说清做了什么）

**research gap 六类（写引言最后一段时对号）：**

| 类型 | 定义 | 例子 |
|---|---|---|
| 知识空白 | X 已知，Y 未知 | 模型已知，但驱动因素分解没在河南做过 |
| 实证空白 | 理论有了，缺某地区/时段/样本的实证 | 其他省做了，河南18市长时序没人做 |
| 方法空白 | 某方法还没应用到这个问题 | LMDI/空间自相关还没用于河南水资源足迹 |
| 对象空白 | 研究集中在某类对象 | 多集中在全国/流域，缺城市尺度 |
| 情境空白 | 其他国家/地区做了，本地没做 | 华北地下水超采区的足迹研究稀缺 |
| 实践空白 | 理论和政策之间有差距 | 核算做了，但怎么落到管理分区不明确 |

### 方法：每个模块三段
1. **模块设计**：输入 → 步骤 → 输出（公式+式中）
2. **为什么需要这个模块**：问题驱动（因为存在X问题，所以用这个方法）
3. **为什么这么做有效**：技术优势（对比其他方法为什么选这个）

### 结果：先盘点模块，再按证据阶梯写

**写Results之前先做"分析模块盘点"**——不要拿到数据就开始写：

1. **列出你做了哪些分析模块**（例：核算→时间变化→空间格局→空间自相关→驱动因素→预测）
2. **每个模块对应Results的一小节**，先定好小节标题和顺序
3. **深度分配不平均**：
   - 和论文novelty最相关的模块 → 深挖（时间趋势+空间格局+驱动解释，2-3页/节）
   - 次要模块 → 一笔带过（1段交代清楚就行）
   - **深度对齐Zotero库里同类SCI论文**：看它们Results分几节、每节几页、几个图，不要自己发明篇幅
4. **砍模块**：如果砍掉某个模块论文novelty还成立，就缩成一段或删掉。
5. **确定每个模块画什么图**：
   - **先看范文用了什么图**：读 `03_论文仓库/ArticleMatrices.md`，扫同类论文的"用了什么图/表"那一行——它们画了几张图、什么类型、怎么组织 Results，你优先参照。
   - **再查通用兜底表**：读 [references/figure-guide.md](references/figure-guide.md)，如果范文没覆盖你的某个分析模块，从这张表里查该画什么图。
   - 最后读 `05_主线设计/图表清单.md`（如果存在），确认图号。

盘点完了，每小节按证据阶梯写：

1. 整体概览（这个指标的空间格局/时间趋势是什么）
2. 方法可信度验证（如果有必要，和已知数据对一下）
3. 主要结果（分指标/分区域展开）
4. 与前人/基线对比（和已有研究结论是否一致）
5. 机制/解释（数据现象往中心意义上靠，但不硬跳政策）
6. 尺度外推（这个发现能不能推广）

每小节开头用"为了验证X，我们做了Y"。

### 讨论：从发现往外扩
1. 核心进展（本文最重要的发现）
2. 证据为何支持这个结论
3. 改变了什么认知
4. 与前人研究的关系
5. 局限
6. 未来工作

**不要重复摆数据**，挑改变解释的关键证据。

### 结论：提炼3-4条
不重复结果，直接给结论。

## 成稿格式（`<章名>.md`）

1. **独立成段、不编号、不分条**：正文是若干自然段，不要"1. 2. 3."或"- "列表。
2. **公式用单行线性 LaTeX**（Word 公式框可识别），如 `EF_{w,i,t}=\gamma_w W_{i,t}/P_w`；**不要用 `$$...$$` 展示块、不要用 `aligned`/`equation` 跨行环境**。行内符号用 `$...$`。公式后紧跟"式中"逐一解释符号与单位。
3. **引用角标**在语言2句末，如 `[3]`、`[4,6-7]`；**参考文献按正文首次出现顺序编号**。
4. **方法章不写"本文"**（参照 2_2data.md 的约定）；引言章可以出现"本文"。
5. **单位符号统一**：hm²、m³·hm⁻²、人⁻¹ 等前后一致；人口万人→人、面积 km²→hm²、水量亿m³→m³ 的换算在正文语言1里交代一句。
6. **文末 `## 参考文献`**：按 GB/T 7714—2015。英文作者姓全大写、名缩写（HOEKSTRA A Y）；刊名斜体可用 *...*；中文文献用中文作者名。编号与正文角标一一对应。

## 过程文件（`<章名>data.md`）

**不要只做一张溯源表**——参照 `2_2data.md` 的完整结构。模板见 [references/process-file-template.md](references/process-file-template.md)，包含：

- 写作命题与章节边界（本节到底算什么、不写什么）
- 术语与符号表（指标 → LaTeX 符号 → 工作簿字段 → 处理原则）
- Zotero 合集读取记录（合集 Key、读了哪几条、各自承担什么、哪条没用）
- 英文文献叙事逻辑表（参考章节怎么组织 → 正文怎么调整）
- 中文口吻校准（参照了哪几本中文核心）
- 数据/工作簿只读核对表（原始单位 → 换算 → 正文公式）
- 公式↔证据对应表（每条公式/参数的首要来源、支撑等级、边界）
- 语言1/语言2 分配清单
- **未写入正文的内容及原因**（考虑过但没采用的模型/参数/指标）
- 输出检查结论

## 两种入口

**A. 从零起草**：用户给章节名，从空白写到成稿。走下面的标准工作流。

**B. 润色/降重/补溯源已有段落**：用户贴来一段已有的中文。先做三步分类，再按规则改：
1. 逐句判断它是语言1（作者衔接）还是语言2（声称引用了文献/给了公式参数）；
2. 语言1：按"反AI痕迹规则"重写，删套话、拆长句、补具体信息；
3. 语言2：逐句核对有没有本会话读过的原句对应——**没有原句的，撤掉引用角标、改成语言1，或标注"待补文献"**，绝不能保留一个对不上原文的 `[n]`；
4. 改完仍按同一成稿格式输出，过程文件照旧回填。

## 标准工作流

1. **澄清**：章节主题、输出文件名、要覆盖哪些公式/结果、必引文献。
2. **读术语表**：如果项目 `05_主线设计/术语表.md` 存在，先读它，确保本章节术语叫法和前文一致。遇到新术语（首次出现的指标/概念），写完后追加到术语表。
3. **定章节边界**：先列出"本节写什么 / 不写什么"，给用户确认后再动笔（尤其方法节，防止堆教材公式）。
4. **盘点数据**：涉及方法/参数时读用户计算表，列出本节真的算了的公式与单位换算口径。
5. **取文献（zotero-cli）**：
   - **先 `zotero-cli config` 确认库可达。失败/命令不存在/Zotero 桌面版没开：停下来明确告诉用户"Zotero 连不上，无法取原文"，**不要在没连上库的情况下开写语言2**——那一定会变成凭记忆编造。
   - 用户的"sample/英文"合集键为 `LWF2MDA4`，优先遍历：`zotero-cli --json get collection-items LWF2MDA4 --limit 100`，再按主题筛；必要时 `zotero-cli --json search "<主题>" --limit 10 --detail keys_only` 补充。
   - 对 3–5 篇最相关的 `get metadata` + `get fulltext`（或 `read <key> --start-page --end-page` 只读方法/结果段，省 token）。
   - 过程文件里记录：哪条读了、读了哪段、承担正文哪句、哪条没用及原因。
6. **拆叙事 + 学口吻**：从这几篇英文文献的该章节总结段落顺序（定义→公式→参数→判别），作为正文结构参照；**同时读 2–3 篇中文文献的同章节**，提取它们的段间衔接句、数据交代句的写法，语言1照此口吻写，不自造腔调。句子不照搬。
7. **写成稿**：按两种语言约定和成稿格式产出。**只写六类成稿内容**（对象/数据/公式/参数/换算/处理方式）；任何解读性句子只在对话反馈里给用户，不进 .md。
8. **写过程文件**：按模板逐项回填，特别注意"语言2句子↔原句↔Key"对照表。
