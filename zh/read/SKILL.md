# read — 文献调研与批量精读笔记

把"写论文前先读一批文献"这件事拆成两段可控流程：**A. 选题前调研 → B. 批量精读落笔记 → C. 跨篇综合**。每篇论文读完都在本地落一个 `.md` 笔记，长期可检索，不依赖 AI 记忆。

> 本 skill 只在用户显式唤起时使用。以下示例以水资源生态足迹研究为例，替换为用户实际研究对象即可。

## 铁律

1. **不编造**。笔记里的章节标题、数据、公式、结论必须来自 PDF 真实读到的文字；读不到就标"未提取/待人工看"，不凭摘要猜。
2. **zotero-cli 连不上就停下**。先 `zotero-cli config` 确认本地或 web 模式可用；失败告诉用户，不要用"印象中这领域有哪些论文"代替检索。
3. **每篇笔记落盘**。读完一篇写一篇 `Article/<论文题目>.md`，并在 `ArticleMatrices.md` 追加一行卡片；不许读完一批只在对话里总结。
4. **分批**。每批 3–5 篇，批与批之间把结果写盘再继续，避免上下文爆掉后前面读过的内容丢失。
5. **先问后做**。A 阶段必须先拿到用户的专业/方向/目标期刊/参考文献质量再检索；B 阶段必须确认合集 Key 和输出文件夹路径。

## 输出结构（固定）

每读完一批，文件落在用户指定的笔记文件夹里，结构固定如下：

```
<notes folder>/
├── Article/
│   ├── <PaperTitleA>.md        # 每篇一份，表格转 markdown 内嵌；图片只用文字描述，不抽 PNG
│   ├── <PaperTitleB>.md
│   └── ...
├── ArticleMatrices.md         # 【目录卡片】每篇一段粗略索引，AI 先扫这个定位
└── _reading-progress.md        # 已读/待读/放弃
```

- **Article/<论文题目>.md**：按 [references/paper-note-template.md](references/paper-note-template.md) 填。文件名取论文完整题目（过长就截前 30 字，去掉 `\ / : * ? " < > |`）。
- **表格**：用 pdfplumber 抽出后转 markdown 表格直接嵌在 md 对应章节下，不单独存 CSV。
- **图片**：**不抽 PNG、不嵌图片文件**。在 md 对应位置用文字写："图N：<图题>——<大致描述/分析结果，2–3句>"。读不到图就写"图N：<图题>（位置第N页，未能自动读取，需人工看）"，不瞎猜。
- **ArticleMatrices.md**：**不是深度对比表，是"快速定位卡片"**。每读完一篇就往里追加一段（见 [references/article-matrices-template.md](references/article-matrices-template.md)）。以后 AI 要找"谁做过[某地区]的[某指标]""谁用了[某方法]"这类素材，先扫这份 20 行的卡片，再决定打开哪篇 Article 文件，避免把 50 篇 PDF 全塞进上下文。
- **_reading-progress.md**：每篇一行（题目 / 状态 / 笔记路径）。

## 三种入口

**A. 选题前调研（还没建 Zotero 合集时）**

先问用户四件事，缺一项就问一项：
1. 专业与研究方向（例：[某指标] / [某研究区]）
2. 想投的目标期刊（例：[目标期刊名]）——**参考文献质量与目标期刊对齐**
3. 时间范围（例：近 10 年 / 经典文献不限）
4. 大致需要多少篇初筛（例：30–50 篇进合集，其中精读 10–15 篇）

然后：
- 用 `zotero-cli search` / `search --mode semantic` 在已有库里找；
- 库内不够时，**给出中英文布尔检索式**（见下），让用户自己去 Google Scholar / Web of Science 导出 RIS/BibTeX 再导入 Zotero（不要替用户在网页上瞎点）；
- 给出一个**初筛排序**：按"该不该读"五个维度打分（见下），排"必读 / 选读 / 略读"三档，让用户确认哪些进精读清单。

### 检索式构造模板

按用户的研究主题，构造中英文各一组布尔检索式。**以下示例以"水资源生态足迹/河南省"为例，替换为用户的实际主题词。**

**中文（CNKI / 万方）**：
```
主题=(<核心概念1> OR <核心概念2>) AND (<研究对象/区域>) AND (<方法/视角>)
```
示例：`主题=(水资源生态足迹 OR 水足迹) AND (河南 OR 河南省) AND (时空 OR 空间 OR 动态)`

**英文（Web of Science / Scopus）**：
```
("<concept 1>" OR "<concept 2>")
AND (<study object/region>)
AND (<method/perspective>)
```
示例：`("water ecological footprint" OR "water footprint") AND (Henan OR "Henan Province") AND (spatial OR "spatiotemporal" OR "temporal variation")`

规则：
- 同义词用 OR 括起来，不同概念用 AND 连接；
- 时间范围用数据库的过滤器设（例：PY=2015–2025），不写进检索式；
- 先跑宽检索式看结果量，太多就加 AND 收窄（比如加具体方法名），太少就删一个 OR 同义词。

### "该不该读"评价五维度（不看期刊牌子）

每篇候选文献按下面五个维度打 1–5 分，总分 ≥18 必读、12–17 选读、<12 略读：

| 维度 | 问什么 |
|---|---|
| **方法相似性** | 用的方法/模型和你计划用的是否一致（[你的方法]？[你的模型]？） |
| **架构可借鉴性** | 它的章节组织、分析路径你能不能直接套用 |
| **解释方式** | 它怎么把数据现象往意义上靠——桥段你能不能学 |
| **创新性** | 它在这个领域提出了什么新东西（新指标/新数据/新方法） |
| **领域奠基性** | 它是不是这个方向的经典/被广泛引用的源头文献 |

**不看的维度**：期刊影响因子、是不是顶刊、作者头衔。这些和你"要不要学它"无关。

**B. 批量精读（Zotero 合集已建好）**

先问：
- 合集 Key（用户提供，或从 Zotero 中查询）；
- 本地笔记输出文件夹（例：`03_papers/`）；
- 本批要读哪几篇（或直接说"从合集里排前面的开始"）。

然后对每篇走"单篇提取流程"（见下）。

**C. 跨篇综合（精读 5 篇以上后，可选）**

`ArticleMatrices.md` 是每读完一篇就追加的浅卡片，不是深度对比。要做深度综合时，另生成一份 `_综合矩阵.md`：横向每篇一列，纵向方法/数据/结论/空白四行，末尾写"研究空白与本文切入点"。模板见 [references/collection-synthesis-template.md](references/collection-synthesis-template.md)。用户没明确要深度综合时，只维护 ArticleMatrices.md 即可。

**研究空白（research gap）必须按六类对号，不能拍脑袋**：

| 类型 | 定义 | 怎么从笔记里找（示例以水资源生态足迹为例） |
|---|---|---|
| 知识空白 | X 已知，Y 未知 | 各篇都做了A，没人做B |
| 实证空白 | 理论有了，缺某地区/时段/样本 | 都在长江/全国做，没人做[研究区]长时序 |
| 方法空白 | 某方法还没应用到这个问题 | 都只做核算，没人用LMDI分解/空间自相关 |
| 对象空白 | 研究集中在某类对象 | 都在流域/省域，缺城市尺度 |
| 情境空白 | 其他地区/条件做了，本地没做 | [类似地区]的足迹研究稀缺 |
| 实践空白 | 理论和政策之间有差距 | 核算做了，但怎么落到管理分区不明确 |

写空白段时，先标清本文占了哪几类，再说"本文从X角度切入"。

## 单篇提取流程（每篇都走一遍）

对一篇 PDF：

1. **元数据**：作者、年份、题目、期刊、DOI、Zotero Key、语种（中/英）。
2. **章节树（一二三级标题）**：用 `zotero-cli outline <key>` 或 PDF 目录提取；没有目录就按字号/加粗启发式分。这是后续 AI 快速定位的索引。
3. **逐章摘要**：引言 / 数据与方法 / 结果 / 讨论 / 结论，每章 3–5 句。
4. **表格与图片（全部以文字形式嵌在本 md 里）**：
   - 表格：用 pdfplumber 抽出后转 markdown 表格直接贴在对应章节，不单独存 CSV；
   - 图片：**不抽 PNG、不嵌图片**，在对应位置写"图N：<图题>——<大致描述/分析结果，2–3句>"；读不到图就标"图N：<图题>（第N页，未能自动读取，需人工看）"，不瞎猜。
5. **数据与数据来源**：本文用了哪些数据？什么年份、什么空间范围、从哪拿的（统计年鉴 / 遥感 / 模型输出 / 问卷）？单位是什么？这是用户自己复现时最关心的。
6. **公式与方法**：列出关键公式（单行 LaTeX）、参数取值、判别标准。
7. **结论与可引用点**：作者最后一句话主张是什么？哪几句可以被用户的论文引为"已有研究表明…"——**逐句摘录原句**（中文原句或英文原句），后面 write skill 直接拿来当语言2的素材。
8. **批判/可借鉴/可攻击**：这篇方法有什么局限？数据有什么问题？哪些地方是用户可以"做得更好"的切入点？
9. **本文可被用户论文哪个章节用**：引言？方法？结果对比？讨论？打标签。

模板见 [references/paper-note-template.md](references/paper-note-template.md)。

## 我建议补充的功能（你看着删）

以下是你没提、但读文献时常见痛点，我加进来了：

- **[建议] 阅读优先级三档**：初筛时就标"必读 / 选读 / 略读"，不要 50 篇平均用力。
- **[建议] 每篇笔记落盘而非只在对话里说**：读过就忘的根本原因是笔记没持久化；每篇一个 `.md`，半年后还能 grep。
- **[建议] 跨篇综合矩阵**：单篇笔记读完就散了，必须有一张横向对比表才能看出"大家都在[某方法]做[某地区]研究，但没人做[你的研究区长时序]"这种空白。
- **[建议] 研究空白段**：综合矩阵末尾单独写"已有研究做到哪一步 / 还没做什么 / 本文从哪切入"——这是引言最后一段的直接素材。
- **[建议] 可引用原句摘录**：把笔记里"作者原句"单独成块，write skill 跑语言2时直接读这些笔记就能取原句，不用再回 PDF。
- **[建议] 进度跟踪**：合集里哪些已读（写过笔记）、哪些待读、哪些放弃，在 `_reading-progress.md` 里维护一行状态，避免重复读或漏读。
- **[建议] 前向/后向引用提示**：对 1–2 篇核心文献，提醒用户"这篇被谁引了 / 它引了哪些关键文献"，帮你快速扩展合集——但不替你下判断加哪些。

## 工作流（一次完整跑）

1. **确认入口**：A（还没合集）还是 B（已有合集）。
2. **A 阶段**：问清专业/方向/期刊/质量/数量 → 检索 + 排序 → 用户确认精读清单。
3. **B 阶段**：确认合集 Key 和输出文件夹 → 每批 3–5 篇：
   - `zotero-cli get metadata <key>` 拿元数据；
   - `zotero-cli get fulltext <key>` 或 `read <key> --start-page --end-page` 分段读；
   - 用 Python（pdfplumber）抽表格转 markdown 内嵌；图片不抽文件，只在 md 里用文字描述图题和大致分析。
   - 按模板写 `Article/<论文题目>.md` 落盘；
   - 在 `ArticleMatrices.md` 追加一段该论文的卡片；
   - 更新 `_reading-progress.md`。
4. **C 阶段（可选）**：精读满 5 篇且用户要深度综合时，生成 `_综合矩阵.md` 和研究空白段；否则只靠 ArticleMatrices.md 索引。
5. **交付**：告诉用户笔记文件夹路径、读了几篇、ArticleMatrices.md 在哪。

## 交付前自检

- [ ] 每篇笔记都落盘到 `Article/<论文题目>.md`，不是只在对话里总结。
- [ ] 每篇笔记里有：章节树、数据来源、关键公式、可引用原句、批判/切入点。
- [ ] 每读完一篇，`ArticleMatrices.md` 都追加了对应卡片。
- [ ] 表格已转 markdown 内嵌在 md；图片以文字描述图题+大致分析，未抽 PNG 文件，读不到的图标了"待人工看"。
- [ ] `_reading-progress.md` 已更新（已读/待读/放弃）。
- [ ] 没有凭摘要猜结论；所有结论性句子在笔记里标了页码或原句位置。
