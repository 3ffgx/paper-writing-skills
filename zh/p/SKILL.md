# p — 图表规划与管理

帮用户解决"这篇论文该画什么图、我现在的数据够不够画、图件文件放哪"。

## 铁律

1. **不直接画图**。p 只做规划（建议画什么、数据够不够、文件放哪），实际作图在 Origin/ArcMap/GeoDa 里由用户自己完成。
2. **先评估数据，再建议图**。不要上来就说"你应该画Moran散点图"——先检查用户手头有没有空间权重矩阵、有没有算好Moran's I值，缺什么先说。
3. **建议必须可追溯**。每张图建议都要回答：数据从哪个文件来、画出来放 08_figures/哪个子文件夹、对应论文章节。
4. **先问后做**。用户没说清要画什么、用什么工具、数据在哪，就先问。

## 四个入口

### A. 全图规划（p skill 启动后的默认动作）

用户跑 p skill 准备画图时，**先做全图规划**，不要等用户一张一张问：

1. **读论文大纲**：`05_outline/outline.md`，看 Results 章分了几节、每节写什么
2. **读范文**：`03_papers/ArticleMatrices.md`，看同类论文 Results 用了几张图、什么类型
3. **盘点手头数据**：`01_data/raw/` 和 `04_experiments/results/` 里有什么
4. **逐节给建议**：Results 每一节该画什么图、参考了哪篇范文的画法、手头数据够不够画
5. **输出一张总表**：

| 章节 | 建议画什么图 | 参考范文 | 需要的数据 | 手头有没有 | 缺什么 |
|---|---|---|---|---|---|
| 4.1 时间变化 | 人均WEF逐年折线图 | He2024 Fig2 | 逐年人均EF/EC | ✅ 有 | 无 |
| 4.2 空间格局 | 多年平均分级设色图 | He2024 Fig5 | 年均值+边界shp | ✅ 有 | 无 |
| 4.3 空间自相关 | Moran散点图+LISA图 | Rey2006 | 空间权重矩阵 | ❌ 缺 | 需在GeoDa建queen权重 |
| 4.4 驱动因素 | LMDI堆叠柱状图 | Su2020 | 分解后各效应值 | ❌ 缺 | 需先跑LMDI分解 |
| 4.5 预测 | 历史vs预测折线图 | Liu2018 | GM(1,1)预测值 | ❌ 缺 | 需先跑预测模型 |

6. **等用户逐节确认**：用户说"4.1这个图可以"或"4.4不做了"，再进入建文件夹环节

### B. 单张图数据够不够（用户单独问某张图时）

用户问"我现在的数据够不够画XX图"时：

1. 盘点手头数据（`01_data/raw/`、`04_experiments/results/`）
2. 对照 write skill 的 `references/figure-guide.md`，这张图需要什么数据
3. 评估：够→告诉用户可以画；不够→缺什么说什么
4. 问用户是否采纳

### C. 建图件文件夹（08_figures/ 管理）

用户确认画某张图后：

1. 在 `08_figures/<platform>/FigX_name/` 下建文件夹
2. 放三类文件：工程文件（.opj/.mxd/脚本）、绘图数据（复制过来）、最终图件
3. 在 `05_outline/figure-list.md` 登记一行

## 08_figures/ 的目录结构

```
08_figures/
├── origin/
│   ├── Fig2_perCapitaWEF/
│   │   ├── Fig2.opj              # Origin工程
│   │   ├── Fig2_data.csv        # 绘图数据
│   │   └── Fig2.tif             # 最终图
│   └── Fig6_LMDI/
├── arcmap/
│   ├── Fig3_spatialPattern/
│   │   ├── Fig3.mxd             # ArcMap工程
│   │   ├── Fig3_data.shp        # 空间数据
│   │   └── Fig3.tif
│   └── Fig5_LISA/
├── geoda/
│   └── Fig4_MoranScatter/
└── python/
    └── Fig7_forecast/
```

**规则**：
- 每个图一个子文件夹，文件夹名 = `FigX_name`（英文命名，避免路径编码问题）
- 工程文件、数据、最终图放同一个文件夹里，不要散在各处
- 数据文件从 `01_data/raw/` 或 `04_experiments/results/` **复制**过来（不是移动），原始数据不动

## 标准工作流

1. **p skill 启动** → 默认走入口A（全图规划）
2. **读论文大纲**：Results 分几节
3. **读 ArticleMatrices.md**：范文怎么展示图表
4. **盘点手头数据**：`01_data/raw/`、`04_experiments/results/`
5. **输出总表**：每节该画什么图、参考哪篇范文、数据够不够、缺什么
6. **用户逐节确认**：哪些采纳、哪些不做
7. 用户确认某张图后 → 在 `08_figures/` 对应平台下建文件夹 → 在 figure-list.md 登记

## 交付前自检

- [ ] 先读了论文大纲，不是凭空说该画什么图
- [ ] 参考了范文的图表组织方式
- [ ] 每节建议都评估了手头数据，缺什么明确说了
- [ ] 输出了总表让用户逐节确认，没有自动开画
- [ ] 用户确认后才建 `08_figures/` 文件夹
- [ ] 在 figure-list.md 登记了每张图
