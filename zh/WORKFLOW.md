# 学术论文 AI 辅助写作工作流

> 一套为中文地学/资源环境类 SCI 论文设计的自定义 skill 组合。
> 核心原则：AI 只做辅助，不替你思考；所有引用必须可溯源；一次只写一节，不生成全文。

---

## 一、这套工作流是什么

你在和 AI（豆包/Codex/任意支持 skill 的客户端）对话时，通过**手动输入特定指令**触发 4 个独立 skill。每个 skill 管论文写作的一段流程，互不越界：

```
ENGINE START          → 建项目骨架（一次性）
"用 read" / "/read"   → 读文献、落笔记
"用 write" / "写X节"  → 逐节写论文正文
"画图" / "这数据能画什么" → 规划图表、评估数据
```

**关键设计：所有 skill 都是手动唤起的，不会自动触发。** 你不发指令，AI 不会自作主张开始写作或画图。

---

## 二、触发指令与操作对照表

| 你说什么 | 触发哪个 skill | AI 做什么 |
|---|---|---|
| `ENGINE START` | **engine** | 在当前目录生成 8 个英文文件夹 + README + 3 个模板（大纲/术语表/图表清单） |
| "用 read 读文献" / "/read" | **read** | 问你专业/方向/目标期刊 → 给检索式 → 你导入 Zotero → AI 批量精读、每篇落一份 .md 笔记 |
| "用 write 写 3.1 节" | **write** | 先问你写什么、边界在哪 → 读 Zotero 原文 → 写成稿 .md + 溯源过程文件 data.md → 停下来等你审核 |
| "画图" / "这数据能画什么" | **p** | 读你的论文大纲 + 范文笔记 → 盘点手头数据 → 输出一张"每节该画什么图、数据够不够"的总表 |

### 不触发什么

- 你只是泛泛说"帮我写论文"——**不触发 write**，AI 会问你要用哪个 skill
- 你只是说"这篇文献讲了什么"——**不触发 read**，那是普通对话
- 你没说 `ENGINE START`——**不建文件夹**

## 三、完整工作流怎么跑

按时间顺序，一篇论文从立项到成稿经过 7 个阶段：

### 阶段 0：项目初始化（engine，一次性）

```
你在项目根目录输入：ENGINE START
```

AI 生成：

```
project-root/
├── 01_data/raw/              ← 原始数据（只读，AI 不许碰）
├── 02_literature/            ← 检索式、导出的 RIS/BibTeX
├── 03_papers/                ← read skill 的笔记工作区
│   ├── Article/              ←   每篇论文一个 .md
│   ├── ArticleMatrices.md    ←   目录卡片（AI 先扫这个定位）
│   └── _reading-progress.md
├── 04_experiments/
│   ├── code/                 ← 你的 Python/R 脚本
│   ├── results/              ← 脚本输出
│   └── logs/                 ← 每次改参数记一笔
├── 05_outline/               ← 论文中心论点、章节大纲
│   ├── outline.md
│   ├── terminology.md
│   └── figure-list.md
├── 06_temp/                  ← AI 过程文件，定稿前清理
├── 07_draft/                 ← write skill 的成稿输出
└── 08_figures/               ← p skill 的图件工作区
    ├── origin/
    ├── arcmap/
    ├── geoda/
    └── python/
```

### 阶段 1：文献调研（read 的 A 阶段）

```
你说："用 read，我想写河南省水资源生态足迹，目标期刊 JCP"
```

AI 问你 4 件事：专业方向、目标期刊、时间范围、大概精读多少篇。然后：

1. 在你已有 Zotero 库里搜
2. 不够的话给你中英文布尔检索式（你自己去 Google Scholar / WoS 导出 RIS 导入 Zotero）
3. 按 5 个维度给候选文献打分（方法相似性/架构可借鉴性/解释方式/创新性/领域奠基性），**不看期刊影响因子**
4. 排"必读/选读/略读"三档，你确认哪些进精读清单

### 阶段 2：批量精读（read 的 B 阶段）

```
你说："用 read，合集 Key 是 LWF2MDA4，从前面开始读"
```

AI 每批读 3-5 篇，每篇：

1. 用 zotero-cli 读 Zotero 里的 PDF 全文
2. 用 pdfplumber 抽表格转 markdown
3. 图片不抽 PNG，只在 .md 里写"图N：图题——大致描述"
4. 落盘到 `03_papers/Article/<题目>.md`
5. 在 `ArticleMatrices.md` 追加一张卡片（10 行以内，含"用了什么图/表"）
6. 更新 `_reading-progress.md`

### 阶段 3：主线设计（你手动 + AI 讨论）

在 `05_outline/outline.md` 里写：
- 论文题目
- **中心论点（一句话）**：这篇论文要证明什么
- 一二三级标题树
- 每节"要做什么"

这一步目前主要靠你自己想，AI 可以帮你从 read 的笔记里提炼 research gap（六类对号：知识空白/实证空白/方法空白/对象空白/情境空白/实践空白）。

### 阶段 4：图表规划（p）

```
你说："画图"
```

AI 做全图规划：

1. 读 `05_outline/outline.md`：Results 分几节
2. 读 `03_papers/ArticleMatrices.md`：同类论文画了几张图、什么类型
3. 盘点 `01_data/raw/` 和 `04_experiments/results/`：你手头有什么数据
4. 输出一张总表：

| 章节 | 建议画什么图 | 参考范文 | 需要的数据 | 有吗 | 缺什么 |
|---|---|---|---|---|---|
| 4.1 | 人均WEF逐年折线 | He2024 Fig2 | 逐年EF/EC | ✅ | 无 |
| 4.3 | Moran散点+LISA | Rey2006 | 空间权重矩阵 | ❌ | 需GeoDa建权重 |

5. 你逐节确认哪些采纳、哪些不做
6. 确认后 AI 在 `08_figures/` 下建 `FigX_name/` 文件夹

### 阶段 5：逐节写作（write）

```
你说："用 write 写 3.1 水资源生态足迹模型"
```

AI 的标准流程：

1. **先问清楚**：写什么、输出文件名、覆盖哪些公式、必引文献
2. **定章节边界**：列"本节写什么/不写什么"，你确认
3. **读术语表**（`05_outline/terminology.md`）：保持叫法一致
4. **盘点数据**：读你的计算表（如 main2.xlsx）
5. **取文献**：zotero-cli 读 Zotero 原文（连不上就停，不瞎编）
6. **拆叙事 + 学口吻**：读 2-3 篇英文方法论文学句式，2-3 篇中文核心学衔接
7. **写成稿** `07_draft/3.1/3.1.md`：
   - 独立成段、不编号不分条
   - **语言1**（作者衔接，不加粗）：用什么数据、怎么换算
   - **语言2**（引用文献，**全部加粗**）：定义、公式、参数
8. **写溯源过程文件** `07_draft/3.1/3.1data.md`：
   - 每条语言2 对应原句 + Zotero Key
   - 公式↔证据对应
   - "考虑过但没采用的内容及原因"
9. **停下来**：把两个文件交给你审核，等你说"可以，写下一节"

### 阶段 6：你手动画图 + 在 Word 里插图

- 你在 Origin / ArcMap / GeoDa 里按 p 的规划画图
- 图件存到 `08_figures/<平台>/FigX_name/`
- 最终在 Word 里插图、用 Zotero 插件插引用（.md 阶段的 `[n]` 只是临时编号）

## 四、环境与工具依赖

### 必需

| 工具 | 用途 | 安装/配置 |
|---|---|---|
| **Zotero 桌面版** | 文献库，所有引用的来源 | 运行状态，本地模式 |
| **zotero-cli** | AI 从命令行读 Zotero 文献 | 已安装，`zotero-cli config` 确认可用 |
| **Windows** | 当前系统 | — |
| **Python + pdfplumber** | 从 PDF 抽表格转 markdown | pip install pdfplumber |
| **Microsoft Word** | 最终排版 | Zotero Word 插件插引用 |

### 画图工具（你自己用，AI 不替你画）

| 工具 | 画什么 |
|---|---|
| **Origin** | 折线图、柱状图、堆叠图 |
| **ArcMap** | 空间分布图、LISA 聚类图 |
| **GeoDa** | Moran's I、空间权重矩阵 |
| Python（可选） | 快速出图、预测图 |

### 不需要的

- 不需要 GPU
- 不需要服务器（单机跑）
- 不需要 API key（你用 ChatGPT Plus 网页版也行，这套 skill 是装在本地的）
- 不需要 LaTeX（.md 用单行线性公式，Word 公式框可识别）

## 五、4 个 skill 各自的铁律

### write 的铁律（最严）

1. **严禁编造**——公式/参数/数字必须有真实出处，拿不准标"待补"
2. **每条语言2必须贴得出原句**——写不出原句就不加引用角标
3. **数据口径以你的 Excel 为准**——不套教材默认值
4. **分析性结论不写进 .md**——"因而/不能/容易/不宜"这类解读只在对话里说
5. **一次只写一节**——写完必须停下等你审核，严禁连续写多节
6. **结果往中心意义上靠但不硬跳政策**——桥段照文献搭

### read 的铁律

1. 不凭摘要猜结论
2. zotero-cli 连不上就停
3. 每篇笔记必须落盘
4. 分批（3-5 篇一批），写盘再继续

### engine 的铁律

1. 只在 `ENGINE START` 时触发
2. 已有骨架先问，不覆盖
3. `01_data/raw/` 只读

### p 的铁律

1. 不直接画图
2. 先评估数据够不够，再建议图
3. 建议必须可追溯（哪个 CSV、哪个文件夹、哪一节）

## 六、文件之间的数据流

```
Zotero PDF
   │ zotero-cli 读取
   ▼
03_papers/Article/<题目>.md  ──→  ArticleMatrices.md（卡片索引）
   │                                    │
   │                                    │ read 完
   ▼                                    ▼
05_outline/outline.md  ←── 你手动写中心论点 + 章节树
   │
   │ p 读大纲 + 卡片 + 盘点数据
   ▼
05_outline/figure-list.md  ←── 图表登记表
   │
   │ write 读大纲 + 术语表 + 卡片 + Zotero 原文
   ▼
07_draft/<section>/<section>.md      ← 成稿
07_draft/<section>/<section>data.md   ← 溯源表（每句引用↔原句↔Key）
   │
   │ 你在 Word 里：
   ▼
最终论文.docx（Zotero 插件自动管编号和参考文献列表）
```

## 七、你每天的典型操作

1. **开工**：打开 Zotero 桌面版
2. **想读文献**：说"用 read"→ AI 给检索式/读笔记
3. **想写一节**：说"用 write 写 X.X"→ AI 写 + 溯源 → 你审核
4. **不知道画什么图**：说"画图"→ p 给总表 → 你确认
5. **改了参数/数据**：在 `04_experiments/logs/` 追加一条日志
6. **写完所有节**：把 .md 内容粘到 Word，用 Zotero 插件插引用、插图、排版

## 八、局限（目前还没做的）

| 缺什么 | 现状 |
|---|---|
| 摘要写作 | 没有 abstract.skill，你自己写 |
| 中心论点提炼 | 主要靠你自己想，AI 可以帮你从 read 笔记里找 gap 但不替你定 |
| 终稿检查 | 没有"全文写完后查术语一致/图号冲突/引用遗漏"的 skill |
| 英文润色 | write 只写中文成稿；中文论文投 SCI 还要自己翻成英文 |
| 审稿回复 | 投稿后再议 |
